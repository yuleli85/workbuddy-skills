# 写法速查

## 一、测试配置（测试配置.yaml）

| 项 | 说明 |
|---|---|
| `name` | 报告标题 |
| `baseUrl` | 被测前端的网址。跑的时候可以用 `--base` 或环境变量 `AUTOTEST_BASE_URL` 换成别的环境 |
| `vars` | 预设变量，用例里 `${名字}` 取 |
| `login.steps` | 在登录页上一步步操作（步骤写法同功能用例）。跑完把登录状态带给后面所有页面 |
| `login.api` | 调登录接口，`save` 存令牌 |
| `login.localStorage` / `sessionStorage` / `cookies` | 打开任何页面前先放进浏览器的值，如 `token: ${token}` |
| `api.base` | 接口地址（和前端不同时写） |
| `api.headers` | 每个接口请求都带的头 |
| `api.business` | 业务错误码规则：`{ path: $.code, ok: [0, 200], msgPath: $.msg }`。后端出错也回 200 的系统必写 |
| `api.match` | 哪些请求算接口（默认浏览器里的 xhr / fetch 都算），如 `[/api/, /admin/]` |
| `api.openapi` | 接口文档逐个调：`url`（或 `file`）、`methods`（默认只 GET）、`params`（路径参数取值，也可按 `"GET /api/user/{id}": {id: 1}` 单独给）、`bodies`（`"POST /api/x": {...}` 给请求体才会测写接口）、`include` / `exclude`、`basePath`、`slowMs`、`defaultQuery` |
| `api.cases` | 接口用例文件，可写通配：`用例/接口/*.yaml` |
| `menus` | 菜单巡检，写 `false` 关掉。见下 |
| `flows` | 功能用例文件 |
| `checks.ignoreRequests` | 这些网址的请求出错不算（字符串含有即可，`/正则/` 也行） |
| `checks.ignoreConsole` | 这些控制台报错不算 |
| `checks.failOnConsoleError` | 控制台报错算「有问题」（默认只算「注意」；程序崩溃类一律算有问题） |
| `browser` | `headless`、`viewport: [宽, 高]`、`channel: chrome`（用本机 Chrome）、`executablePath`、`timeout`（每步默认等多久，毫秒） |
| `report.dir` | 报告放哪，默认配置旁的 `autotest-report/时间/` |

### 菜单巡检 `menus`

| 项 | 说明 |
|---|---|
| `start` | 登录后能看到菜单的页面 |
| `source` | `dom`（默认，点页面菜单）／`api`（从菜单接口取）／`list`（写死） |
| `exclude` | 不点的菜单，名字或网址含这些字就跳过（默认：退出、登出、注销、logout） |
| `dom` | 认不出菜单时自己写：`{ root: '.my-menu', title: '.my-sub-title', sub: '.my-sub', open: 'is-open', leaf: '.my-item' }`；或 `{ profile: antd }` 指定样式 |
| `api` | `{ request: {url: /admin/menu}, list: $.data, name: name, path: path, children: children, skip: { type: "1" } }`（`skip` 按字段值跳过，比如按钮权限、外链） |
| `routePrefix` | 菜单接口给的是路由时，拼网址的前缀，哈希路由写 `/#` |
| `list` | `[ {name: 用户管理, url: /#/admin/user/index}, ... ]` |
| `beforeSteps` | 找菜单前先做的步骤（比如先切到某个系统、关掉公告弹窗） |
| `wait` | 页面安静后再等多久看结果（毫秒，默认 800） |
| `maxWait` | 最多等页面多久（默认 15000） |
| `slowMs` | 超过这么久记「注意」（默认 5000） |
| `errorTexts` | 页面正文开头出现这些字算错误页（默认 404、页面不存在、无权访问、系统异常…） |
| `errorSelectors` | 错误提示框的选择器（默认已含 Element、Ant Design、Arco、Naive、iView、Vant） |
| `content` | 正文区域的选择器（判断空白页、错误页用；默认 .el-main、main、.app-main…） |
| `blankMinText` | 正文少于多少字且没有表格图表表单算空白页（默认 10） |
| `limit` | 只测前几个（调试用） |

每个菜单查这些，任何一条算「有问题」：打不开、页面程序报错（含 Vue / React 吞掉只打到控制台的崩溃）、页面调的接口返回 4xx/5xx 或业务错误码、脚本样式加载失败、弹出错误提示、显示 404 之类的错误页。打开慢、空白页、普通控制台报错算「注意」。

## 二、用例文件

一个文件可以是一个用例，也可以 `cases:` 下列多个：

```yaml
name: 用例名            # 报告里显示
desc: 一句话说明测的是什么规则
tags: [用户, 冒烟]       # --grep 可以按标签或名字只跑一部分
skip: 等后端修完再开     # 写了就跳过
vars: { kw: 张 }        # 本用例的变量
each:                   # 一组数据跑一遍（数据驱动），每行的字段当变量用；有 name 字段用作简称
  - { name: 停用, status: 0 }
  - { name: 启用, status: 1 }
steps: [ ... ]          # 失败就停，后面的步骤记「跳过」
cleanup: [ ... ]        # 不论成败都跑，删测试数据用
```

### 变量
- `${名字}`：取 vars、前面步骤 `save` 存的值、`each` 的字段。整串只有一个 `${x}` 时保留原类型（数字、对象）。
- `${env.名字}`：环境变量（账号密码放这里）。
- 自带：`${now}` 毫秒时间戳、`${date}` 年月日、`${time}` 时分秒、`${rand}` 六位随机数。

### 接口步骤
```yaml
- name: 新增
  api:
    method: POST                      # 默认 GET
    url: /api/user                    # 相对 api.base；也可写完整网址
    query: { current: 1, size: 10 }
    json: { username: autotest_${rand} }   # 或 form: {...}、multipart: { file: { file: ./a.xlsx } }
    headers: { X-Tenant: "1" }
    timeout: 20000
  expect:
    status: 200                       # 不写时：4xx/5xx 算失败
    json: { $.data.id: { exists: true }, $.data.status: 1 }
    body: { contains: 成功 }          # 按纯文字判断
    headers: { content-type: { contains: json } }
    time: 2000                        # 耗时不超过（毫秒）
    business: false                   # 不自动查业务错误码（专门测出错情况时）
  save: { uid: $.data.id }            # 存下来，后面 ${uid} 用；status、body 也能存
```
返回 4xx/5xx 或业务码不对就算失败；`expect.json` 里自己判断了 `code` 的，不再自动查业务码。

### 页面步骤

| 写法 | 作用 |
|---|---|
| `goto: /#/admin/user` | 打开网址（相对 baseUrl） |
| `click: 按钮:保存` | 点击。加 `force: true` 强点 |
| `dblclick` / `hover` | 双击 / 悬停 |
| `fill: { 标签:用户名: 张三, 提示:请输入手机号: "139..." }` | 填一个或多个输入框；也可 `{selector, value}` |
| `type: { selector, value }` | 一个字一个字敲（要触发联想搜索时用） |
| `choose: { selector: 标签:状态, option: 启用 }` | 组件库下拉框选一项；级联写 `option: [广东, 深圳]`；原生 select 也行 |
| `check` / `uncheck` | 勾选 / 取消勾选 |
| `press: Enter` 或 `{ selector, key }` | 按键 |
| `upload: { selector: "input[type=file]", file: ./测试.xlsx }` | 上传（路径相对用例文件） |
| `wait: 1000` / `wait: 文字:加载完成` / `wait: { selector, state: hidden }` / `wait: { idle: true }` | 等 |
| `dialog: dismiss` | 下一个浏览器确认框点「取消」（默认一律点确定） |
| `reload: true` | 刷新 |
| `screenshot: 名字` | 整页截图放进报告 |
| `saveText: { selector, as: 变量名, regex: "单号：(\\w+)" }` | 把页面上的字存成变量 |
| `js: "document.title"` + `expect` / `save` | 在页面里跑一段脚本取值 |
| `set: { a: 1 }` | 设变量 |

任何页面步骤都可以加 `response:`，在这一步操作时等它触发的接口并判断：
```yaml
- click: 按钮:查询
  response: { url: /api/user/page, method: GET, expect: { json: { $.data.records: { every: { status: 1 } } } }, save: { total: $.data.total } }
```
`url` 写网址里的一段（含有即可）或 `/正则/`。

每一步结束后，页面要是冒出程序报错或 5xx 接口，这一步算失败；专门测出错的步骤加 `allowErrors: true`。每步都可加 `name`（报告里显示）和 `timeout`。

### 页面判断

| 写法 | 判断 |
|---|---|
| `expectText: 保存成功` 或 `{ selector, text }` | 页面（或某块）里有这段字；`text: /正则/` 也行 |
| `expectNoText: { selector, text }` | 没有这段字 |
| `expectVisible: 按钮:提交` / `expectHidden: .el-dialog` | 看得见 / 看不见 |
| `expectUrl: /home` | 网址含有 |
| `expectCount: { selector: ".el-table__row", gte: 1 }` | 个数（判断写法见下） |
| `expectValue: { selector: 标签:用户名, value: 张三 }` | 输入框里的值 |
| `expectToast: 成功` | 弹出了含这段字的提示消息 |

### 选择器
- 普通 CSS：`#save`、`.el-table .el-table__row`；Playwright 写法也认：`text=保存`、`xpath=//button`。
- 中文简写：`按钮:保存`（按钮名含有）、`文字:新增成功`、`标签:用户名`（表单标签，整句一致）、`提示:请输入用户名`（输入框灰字提示，整句一致；前面加 `~` 表示含有即可：`提示:~用户名`）、`角色:link:首页`、`测试id:save-btn`。
- 同名的多个时：`{ selector: .el-table__row, nth: 0 }`、`{ selector: .el-table__row, hasText: 张三 }`、`{ ..., last: true }`。

### 判断写法（json 字段、个数、js 结果都通用）

直接写值就是「等于」（数字和数字字符串算相等）。复杂的写成对象：

| 写法 | 意思 |
|---|---|
| `{ eq: 1 }` / `{ ne: 0 }` | 等于 / 不等于 |
| `{ gt: 0 }` `{ gte: 1 }` `{ lt: 100 }` `{ lte: 100 }` | 大小 |
| `{ contains: 张 }` / `{ notContains: x }` | 文字含有；对列表是「含有这一项」 |
| `{ matches: "^1\\d{10}$" }` | 正则 |
| `{ exists: true }` / `{ empty: false }` | 有这个字段 / 不是空的 |
| `{ type: array }` | 类型：string、number、boolean、array、object、null |
| `{ len: 10 }` `{ lenGte: 1 }` `{ lenLte: 20 }` | 长度 |
| `{ in: [0, 1] }` / `{ notIn: [...] }` | 是其中之一 |
| `{ every: { status: 1, name: { contains: 张 } } }` | 列表**每一条**都满足（筛选、搜索的逻辑就靠它） |
| `{ some: {...} }` / `{ none: {...} }` | 至少一条 / 没有一条满足 |
| `{ sorted: desc }` | 列表按从大到小（`asc` 从小到大）排好 |
| `{ not: {...} }` | 取反 |

路径写法：`$.data.records[0].name`、`$.data.records[*].id`（取出一列）、`$.data.records.length`、`$['带.点的键']`。

## 三、命令

```bash
node scripts/autotest.js init <目录>                  # 生成配置和用例模板
node scripts/autotest.js check <配置>                 # 只查用例文件写法
node scripts/autotest.js run <配置>                   # 全跑
  --only menus,api,flows                              # 只跑其中几类
  --grep 用户                                         # 只跑名字或标签含「用户」的菜单和用例
  --headed                                            # 弹出浏览器看着跑
  --base http://test.xxx.com                          # 换被测地址
  --out <目录>                                        # 报告放哪
```
退出码：0 全部通过，1 有问题，2 配置写错或没跑起来。可直接放进流水线，`junit.xml` 给流水线展示。

报告目录里：`report.html`（浏览器打开，可勾「只看有问题的」）、`results.json`（全部明细，含每个菜单调到的接口和返回样例）、`junit.xml`、`shots/`（截图）。
