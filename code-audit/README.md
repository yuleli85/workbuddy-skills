# 代码审计技能（code-audit）

给 AI 编程工具（Claude Code 等支持技能的工具）用的代码审计技能，也可以直接当命令行工具用。用来验收外包交付、审供应商代码、上线前检查、审一次改动。

## 查什么

| 方面 | 内容 |
|---|---|
| 功能是否实现 | 需求逐条对照代码，判已实现 / 部分实现 / 未实现 / 与需求不一致；核心规则实测；没做完的标记、空壳方法、写死的模拟数据 |
| bug | 边界条件、金额用浮点数、状态流转、吞掉异常、资源没关、配置项缺失导致启动失败、各语言常见陷阱 |
| 安全漏洞 | 越权、未登录可访问、SQL 和命令注入、上传、反序列化、口令和密钥写死、口令存储、验证码和令牌、跨站脚本、跨域、调试入口 |
| 实现是否合理 | 分层、超长文件和函数、重复代码、写死的地址、数据库设计、查询性能、日志和错误处理 |
| 交付物是否完整 | 源码、用户使用手册、部署手册、接口文档、数据库脚本、构建和启动脚本、配置样例、测试和测试报告、版本说明、许可证；**按内容要点检查**，不只看有没有文件 |
| 另外补充 | 组件已知漏洞和许可；密钥泄露（含提交历史）；代码读的配置项文档里有没有写；自动化测试；个人信息合规和日志里的敏感信息；部署运维脚本里的危险操作；源码里带了不该交的东西 |

自动扫描负责把项目摸清、列出疑点；需求对照、业务逻辑、越权这些扫描查不出的，由 AI 按技能里的清单逐项人工审，每条疑点都要看过代码判断属实还是误报。最后出一份可以直接交给对方的审计报告（网页，可打印成 PDF；另有可转 Word 的版本）。

## 安装

只要 Python 3.8 或以上，不用装其他东西。

可选：装了 [gitleaks](https://github.com/gitleaks/gitleaks) 会自动用它查密钥泄露（含提交历史）；装了 pdftotext 能读 PDF 格式的手册。

装好先跑自检：

```bash
cd code-audit
python scripts/audit.py demo        # Mac / Linux 用 python3
```

演示项目是一个故意埋了问题的订单系统（越权、SQL 注入、满减算错、状态能乱改、导出没做、上传可执行代码、口令写死、用 MD5 存口令、组件有漏洞、手册不全等）。自检会扫描它、套用示例审计结论出报告，最后显示「自检通过」。报告在 `examples/演示项目-审计结果/审计报告.html`，浏览器打开可以看到完整报告的样子。

## 放进 AI 工具

把整个 `code-audit` 文件夹放进工具的技能目录，例如 Claude Code：
- 只给自己用：`~/.claude/skills/code-audit/`（Windows 是 `C:\Users\你的用户名\.claude\skills\code-audit\`）
- 跟项目走：`项目/.claude/skills/code-audit/`

然后跟 AI 说，例如：
- 「用代码审计技能审一下 D:\projects\xxx，对照 docs 里的需求说明，看能不能验收」
- 「审一下这个分支相对 main 的改动」
- 「看看这个项目交付物全不全」

AI 会照 SKILL.md 的步骤：问清代码位置、需求依据、审计目的、约定的交付物和能不能跑 → 扫描 → 跑起来 → 逐项人工审 → 逐条核对扫描疑点 → 写结论 → 出报告，最后交报告和一段话结论。

## 自己用命令行

```bash
python scripts/audit.py scan   <项目目录> -o <输出目录>   # 扫描：出底稿和结论模板
#   编辑 <输出目录>/审计结论.json，写需求对照、问题、疑点核对、交付物、运行验证
python scripts/audit.py check  <输出目录>                # 检查结论写全没有
python scripts/audit.py report <输出目录>                # 出报告
```

`scan` 的选项：
- `-o 目录`：输出目录，默认 `<项目>/审计结果`。
- `--since 版本`：只查这个版本之后改过的文件（审一次改动，要求项目是 git 仓库）。
- `--exclude 目录 ...`：跳过的目录（依赖包、编译产物等常见目录默认已跳过）。
- `--no-tools`：不调 gitleaks 等外部工具。
- `--online`：允许联网检查（npm audit）。

`report --fail-on 严重|高|中`：有这个级别及以上的问题时退出码为 1，可以放进流水线。

转 Word：`pandoc 审计报告.md -o 审计报告.docx`。转 PDF：浏览器打开 `审计报告.html` 打印即可。

输出目录里：

| 文件 | 给谁 |
|---|---|
| 审计报告.html / 审计报告.md | 交给对方的正式报告 |
| 审计底稿.md | 审计的人看：项目概况、交付物、配置一致性、全部扫描疑点 |
| 审计结论.json | 审计的人写的结论，重新扫描不会覆盖 |
| scan.json | 扫描明细 |

## 支持的技术栈

Java（Spring Boot、若依、MyBatis）、JavaScript / TypeScript（Vue、React、Node、小程序、uni-app）、Python（Flask、Django、FastAPI）、Go、PHP、C#，以及 SQL、Shell、Dockerfile、各类配置文件。依赖清单支持 Maven、Gradle、npm（含锁文件）、pip、Poetry、Go 模块。
