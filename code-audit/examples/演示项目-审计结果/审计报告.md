# 订单管理演示系统 代码审计报告

版本：演示版；审计日期：2026-10-27；审计范围：全部源代码（6 个程序文件）、数据库脚本和随附文档

审计依据：《订单管理系统需求说明》R1～R8；README 和《用户使用手册》

## 一、结论

**不建议验收**

8 条需求里 3 条已实现、2 条部分实现、2 条与需求不一致、1 条未实现。安全上有 2 个严重问题：任何登录用户都能查看和修改别人的订单；批量导入接口不用登录，还能通过上传的文件在服务器上执行任意代码。另有满减金额算错、订单状态可以任意改、搜索可被注入读到别人的数据等高级别问题。交付物缺部署手册和接口文档，没有任何自动化测试。建议修完严重和高级别问题、补齐部署手册后重新提交审计。

问题数：严重 2，高 6，中 6，低 0，建议 0

## 三、问题清单

### M01【严重】越权：登录用户可以查看、修改任何人的订单

- 维度：安全
- 位置：`app.py:56`、`app.py:70`、`services/order.py:27`
- 现象：订单详情和修改状态接口按订单编号直接查、直接改，没判断订单是否属于当前用户。实测用户 1 能读到用户 2 的订单。
- 影响：任何注册用户遍历编号就能拿到全部订单（含收货信息），还能把别人的订单改成已完成。
- 修改建议：查询和修改都带上当前用户条件（where id = ? and user_id = ?），查不到返回 404；管理员另走有权限校验的接口。

### M06【严重】批量导入接口不用登录，且上传文件可在服务器上执行任意代码

- 维度：安全
- 位置：`app.py:77`、`app.py:78`、`requirements.txt`
- 现象：导入接口没检查登录；用 yaml.load 解析上传内容，所用 PyYAML 5.3.1 版本可以借此执行任意代码。
- 影响：不用账号就能控制服务器，读取或删除全部数据。
- 修改建议：接口加登录校验；改用 yaml.safe_load 或直接用 JSON；PyYAML 升级到 5.4 以上；导入内容逐项校验。

### M02【高】满减算错：正好 100 元的订单没有减 10 元

- 维度：缺陷
- 位置：`services/order.py:12`
- 现象：条件写成 total > 100，需求是满 100（含 100）。
- 影响：所有正好 100 元的订单多收 10 元，会引发客诉。
- 修改建议：改成 >= 100，并补「99.99 / 100 / 100.01」三个边界的测试。

### M03【高】订单状态可以任意修改，没有按流程控制

- 维度：功能
- 位置：`services/order.py:37`、`services/order.py:40`
- 现象：update_status 直接把状态改成传入的值，定义好的状态顺序没有使用；改库失败时也不报错。
- 影响：可以跳过支付直接变成已完成，或把已完成改回待支付，账目对不上。
- 修改建议：按状态顺序只允许改到下一个状态，其他一律拒绝并提示；失败要返回错误而不是吞掉。

### M04【高】订单导出 Excel 没有做

- 维度：功能
- 位置：`services/order.py:45`、`services/order.py:46`
- 现象：只有一个返回空列表的函数，没有接口和页面入口。
- 影响：需求功能缺失。
- 修改建议：按需求实现导出接口（只导出本人订单），并在用户手册里补操作说明。

### M05【高】订单搜索可被 SQL 注入，能读到别人的订单

- 维度：安全
- 位置：`services/order.py:33`
- 现象：搜索关键字直接拼进 SQL。实测输入「%' or 1=1 --」后，用户 1 搜到了用户 2 的订单。
- 影响：可绕过「只看自己订单」的限制读取全部数据，进一步可能读取用户表。
- 修改建议：改成参数化查询：where o.user_id = ? and i.name like ?，参数传 ('%' + keyword + '%')。

### A02【高】口令或密钥写死在代码里

- 维度：安全
- 位置：`config.py:4`
- 现象：会话签名密钥写死在配置文件里，拿到代码就能伪造任何人的登录状态。
- 修改建议：改成从环境变量或配置中心读取，代码和仓库里只留示例值；已提交过的真实口令要换掉。

### A05【高】用了 MD5/SHA1（用于存口令就是高危）

- 维度：安全
- 位置：`services/user.py:11`、`services/user.py:16`
- 现象：注册和登录都用不加盐的 MD5 存口令。
- 修改建议：存口令改用 bcrypt / argon2 / PBKDF2（加盐、慢哈希）；只做文件校验、缓存键的可忽略。

### M07【中】短信验证码登录没有真正发短信，验证码可预测、可被暴力尝试

- 维度：功能
- 位置：`services/user.py:21`、`services/user.py:22`
- 现象：发送函数只把验证码存在内存里，没有调用短信平台；验证码用普通随机数生成；没有限制发送频率和错误次数；存在内存里，服务重启或多进程部署时会丢。
- 影响：功能实际不可用；接上短信后也有被刷短信和猜中验证码的风险。
- 修改建议：接入短信平台；用 secrets 生成验证码；同一手机号 60 秒内只发一次、错 5 次作废；验证码存 Redis 等共享存储。

### M08【中】缺部署手册和接口文档，用户手册不全

- 维度：交付物
- 位置：`README.md`、`docs/用户使用手册.md`、`config.py:5`、`config.py:6`
- 现象：没有部署手册，README 只写了三条启动命令，没写环境版本、配置项（数据库位置、短信密钥）、生产配置、备份和升级回滚；没有接口文档；用户手册没有截图、角色说明和常见问题，也没写导入、改状态的操作。
- 影响：客户运维人员无法照着部署和维护，后续接手开发要从代码里倒推接口。
- 修改建议：补部署手册（环境要求、配置项清单、初始化、启动、验证、备份、升级回滚、常见问题）和接口文档；用户手册按功能逐个补全操作步骤和截图。

### M09【中】没有任何自动化测试

- 维度：测试
- 位置：`整个项目`
- 现象：项目里没有测试代码，交付材料里也没有测试报告。
- 影响：满减边界、状态流转这类规则改动后无法回归，本次发现的计算问题就是缺测试导致的。
- 修改建议：至少给金额计算、状态流转、越权校验补单元或接口测试，并随交付提供测试报告。

### A01【中】调试开关或管理端点对外开着

- 维度：安全
- 位置：`app.py:85`、`config.py:3`
- 现象：调试模式写死开启且监听所有网卡，出错页面可执行代码。
- 修改建议：生产配置关掉调试、接口文档页和管理端点，或者至少加登录；部署手册写清生产配置怎么设。

### A03【中】金额用浮点数存或算，会有分厘误差

- 维度：缺陷
- 位置：`services/order.py:9`
- 现象：单价用浮点数累加；数据库金额字段也是浮点类型。
- 修改建议：金额用 BigDecimal / Decimal / 整数「分」存和算；数据库用 DECIMAL。

### A04【中】函数默认参数用了可变对象，调用之间会互相串数据

- 维度：缺陷
- 位置：`services/order.py:17`
- 现象：实测连续下两单，第二单的标签变成两个「新订单」。
- 修改建议：默认值写 None，函数里 if x is None: x = []。
