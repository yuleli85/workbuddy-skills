# 审计清单

按维度逐项过；后半部分是各技术栈的常见坑。「扫」表示自动扫描会报疑点（要核对），没标的只能人工看。

## 一、功能是否实现

- [ ] 需求逐条找到实现：接口（路由/控制器）、页面（菜单/路由）、数据表。找不到的就是未实现。
- [ ] 需求里的规则逐条对：边界值（满 100 含不含 100）、取整方式、状态顺序、权限范围、必填和长度校验、默认值。
- [ ] 页面有入口但后端是空壳、返回写死数据、留着「待完成」标记（扫：FUNC-TODO、FUNC-NOT-IMPLEMENTED、FUNC-MOCK-DATA）。
- [ ] 前端有按钮但后端没接口，或后端有接口但前端没调。
- [ ] 能跑的，挑核心流程实测：正常值、边界值、异常值各一组；结果写进报告。
- [ ] 需求之外多做的功能（后门、调试页、未授权的数据上报）。

## 二、缺陷（bug）

- [ ] 比较和边界：`>` 和 `>=`、`<` 和 `<=`、下标从 0 还是 1、分页最后一页。
- [ ] 空值：查不到数据、空列表、空字符串、0、未登录时的用户对象。
- [ ] 金额和数量：浮点数存钱（扫：BUG-MONEY-FLOAT、BUG-BIGDECIMAL-DOUBLE）、四舍五入方式、币种和单位（元/分）、多次折扣的先后。
- [ ] 状态流转：能不能跳步、回退、重复操作（重复支付、重复退款）；并发下两个人同时改。
- [ ] 事务：一个业务改多张表时有没有在一个事务里；出错能不能回滚；事务里调外部接口。
- [ ] 异常：吞掉异常（扫：BUG-EMPTY-CATCH、BUG-PY-EXCEPT-PASS）、出错返回成功、错误信息给用户看到堆栈。
- [ ] 资源：文件、连接、流没关（扫：BUG-UNCLOSED-STREAM）；连接池大小；大文件一次读进内存。
- [ ] 日期和时区：服务器时区、跨天、月底、闰年；SimpleDateFormat 共用（扫）。
- [ ] 语言陷阱：Java 字符串 `==`（扫）、Python 可变默认参数（扫）、JS `==` 和隐式类型转换、整数溢出。
- [ ] 配置：代码读的配置项在配置文件里没定义（扫：BUG-CONF-UNDEFINED），换环境就启动不了。
- [ ] 定时任务：多实例部署时会不会重复执行；执行失败有没有补偿。

## 三、安全

- [ ] **越权**（扫描查不出，必须人工）：每个按编号查、改、删的接口，是否校验数据属于当前用户或当前租户；普通用户能不能调管理员接口；前端隐藏按钮不算权限控制。
- [ ] **未登录可访问**：逐个看放行名单（Spring Security / Shiro 的 permitAll、anon，若依的 `@Anonymous`，中间件白名单），导入、导出、上传、回调接口尤其要看。
- [ ] 注入：SQL 拼接（扫：SEC-SQL-*、SEC-MYBATIS-DOLLAR）、命令执行（扫）、表达式和模板注入、eval（扫）。
- [ ] 上传：文件类型（看内容不只看扩展名）、大小、保存路径是否可执行、文件名（扫：SEC-UPLOAD-NAME）。
- [ ] 下载和文件读写：路径来自参数（扫：SEC-PATH-TRAVERSAL）。
- [ ] 反序列化：fastjson autoType、Java 原生反序列化、yaml.load、pickle（扫：SEC-DESERIALIZE）。
- [ ] 口令和密钥：写死在代码或配置里（扫：SEC-HARDCODED-SECRET、SEC-CONF-SECRET 等）；提交历史里出现过（gitleaks 历史模式）；默认口令和弱口令（扫）。
- [ ] 口令存储：MD5/SHA1 不加盐（扫：SEC-WEAK-HASH）；应使用 bcrypt / argon2 / PBKDF2。
- [ ] 登录：失败次数限制、验证码可预测（扫：SEC-WEAK-RANDOM）、短信接口防刷、会话过期、退出后令牌失效。
- [ ] 令牌：JWT 密钥写死或太短、不校验签名（扫：SEC-JWT-WEAK）、令牌放在网址里。
- [ ] 跨站脚本：直接插入网页代码（扫：SEC-XSS）、富文本没过滤。
- [ ] 跨域放开给所有网站（扫：SEC-CORS-ANY）、跳转地址来自参数（扫）、服务端按参数请求地址（扫：SEC-SSRF）。
- [ ] 传输：关掉证书校验（扫：SEC-TLS-OFF）、对外接口没走 HTTPS。
- [ ] 调试和管理入口：调试模式、Actuator、Druid 监控页、Swagger 在生产开着（扫：SEC-DEBUG-ON）。
- [ ] 报错信息泄露：堆栈、SQL、服务器路径返回给前端。
- [ ] 组件漏洞：底稿「组件」一节（扫：DEP-KNOWN-VULN），核实是否用到有漏洞的功能。

## 四、实现是否合理

- [ ] 分层：控制器里写业务逻辑和 SQL、一个类几千行（扫：REASON-LONG-FILE、REASON-LONG-FUNC）。
- [ ] 重复代码（扫：REASON-DUPLICATE）：复制粘贴改一点的，以后改一处漏一处。
- [ ] 写死的东西：服务器地址（扫：OPS-HARDCODED-IP）、魔法数字、业务参数（费率、天数）应可配置。
- [ ] 数据库：金额用 DECIMAL；常用查询条件有索引；字段长度够用；有没有外键或至少有一致性校验；软删除和唯一索引冲突。
- [ ] 性能：循环里查库或调接口（N+1）、一次查全表、不分页的列表、大事务、没有缓存的热点查询、导出全量数据到内存。
- [ ] 日志：关键操作（登录、支付、改权限）有没有记；日志级别；是否用 printStackTrace / System.out（扫）。
- [ ] 错误处理：统一的错误返回格式；前端能看懂的提示。
- [ ] 可扩展：多实例部署时内存里的状态（会话、验证码、锁）会不会丢或不一致。
- [ ] 只提真影响维护或性能的；命名、空格这类风格问题最多记一条「建议」。

## 五、交付物

详见 `交付物清单.md`。要点：打开看内容，不是看有没有这个文件；部署手册要照着装一遍；接口文档抽几个接口和代码对；配置项和代码对（扫：DELIV-ENV-UNDOC）；源码里不该带的东西（扫：STYLE-JUNK-FILES、SEC-SECRET-FILE）。

## 六、依赖和许可

- [ ] 有漏洞的版本（扫）；版本「待核」的去锁文件或构建结果查。
- [ ] 锁文件有没有提交（package-lock.json / yarn.lock / poetry.lock / go.sum），没有则每次装的版本可能不同。
- [ ] 已停止维护的组件（log4j 1.x、Vue 2、moment、request、pycrypto）。
- [ ] 许可：GPL / AGPL / SSPL 类组件用在闭源商用项目里要评估；交付物里有没有第三方组件清单。
- [ ] 私有仓库地址和内网源写进了构建配置，客户环境拉不到。

## 七、合规（个人信息）

- [ ] 手机号、身份证、银行卡、地址：存储是否加密、展示是否脱敏、导出是否有权限和记录。
- [ ] 日志和打印里有没有口令、令牌、个人信息（扫：SEC-LOG-SENSITIVE）。
- [ ] 收集范围是否超出业务需要；有没有隐私政策和同意记录（App、小程序必查）。
- [ ] 数据出境、第三方共享（统计、推送、地图、短信平台）。

## 八、运维和部署

- [ ] 启动停止脚本、容器配置、进程守护；端口和目录写在手册里。
- [ ] 镜像版本写死（扫：OPS-DOCKER-LATEST）、容器用 root 运行（扫：OPS-DOCKER-ROOT）。
- [ ] 脚本里的危险操作：`rm -rf $VAR`（扫）、`chmod 777`（扫）、下载即执行（扫）、数据库脚本删表（扫：OPS-SQL-DROP）。
- [ ] 数据库升级脚本：有没有版本管理（Flyway / Liquibase / 按版本号命名的脚本）；能不能在已有数据上执行。
- [ ] 健康检查、日志位置和切割、备份和恢复演练、监控告警。

## 九、测试

- [ ] 有没有自动化测试（扫：TEST-NONE）；能不能一条命令跑通；跑出来几个通过几个失败。
- [ ] 覆盖到核心规则没有（金额、状态、权限），还是只有一个自动生成的空测试。
- [ ] 交付物里的测试报告和实际跑出来的是否一致。

## 技术栈专项

### Java / Spring Boot / 若依 / MyBatis
- MyBatis `${}`（扫）；`order by` 排序字段来自前端时要白名单。
- 若依：`@Anonymous` 和 `SecurityConfig` 放行路径；`@PreAuthorize` 是否每个接口都有；数据权限 `@DataScope` 有没有加在该加的查询上；默认口令 admin/admin123 是否已改；Druid 监控页口令；`ruoyi.profile` 上传目录。
- Spring：`@Value` 没默认值又没在配置里定义（扫）；`spring.profiles.active` 生产配置；Actuator 暴露范围；`@Transactional` 加在 private 方法或同类内部调用上不生效；只对运行时异常回滚。
- fastjson 1.x（扫）、log4j（扫）、shiro 默认密钥（rememberMe）。
- 线程池、定时任务 `@Scheduled` 在多实例下重复执行。
- `BigDecimal` 用 `new BigDecimal(double)`（扫）、用 `equals` 比较（扫）。

### 前端：Vue / React / 小程序 / uni-app
- 前端写死的密钥、接口地址（扫）；`.env.production` 里的真实值。
- `v-html` / `dangerouslySetInnerHTML` / `innerHTML`（扫）。
- 权限只在前端做（隐藏按钮、路由守卫），后端没校验——要回到后端查。
- 打包产物有没有带 source map 上生产。
- uni-app / 小程序：`manifest.json` 里的 AppID 和密钥；本地存储里放令牌和个人信息；隐私协议弹窗。

### Node.js
- `child_process.exec` 拼参数（扫）；`eval` / `new Function`（扫）。
- Express 没有限流、没有 helmet；错误处理中间件把堆栈返回前端。
- `npm audit`（`--online` 时自动跑）。

### Python（Flask / Django / FastAPI）
- `DEBUG=True`（扫）、`SECRET_KEY` 写死（扫）。
- `yaml.load`、`pickle.loads`（扫）；`subprocess` 用 `shell=True`（扫）。
- f-string / `%` 拼 SQL（扫）；Django `raw()` / `extra()`。
- 可变默认参数（扫）；`except: pass`（扫）。
- `requirements.txt` 不写版本号。

### Go
- `fmt.Sprintf` 拼 SQL（扫：SEC-SQL-SPRINTF）；`exec.Command` 参数来自外部。
- 忽略错误返回值 `_ =`；goroutine 泄漏；map 并发读写。
- `dgrijalva/jwt-go` 已停止维护（扫）。

### PHP
- `$_GET` / `$_POST` 直接进 SQL 或 `echo`（扫）；`include` 变量路径；`unserialize`（扫）。
