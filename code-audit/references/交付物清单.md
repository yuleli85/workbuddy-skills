# 交付物清单

合同或约定里有清单的照约定查；没有的按下面的通行清单查。每一项都要**打开看内容**，判「齐全 / 不全 / 缺失 / 不适用」，不全的写清缺什么。扫描会按文件名和内容要点先判一遍（底稿第 2 节），只是参考。

| 交付物 | 必须有的内容 | 怎么验 |
|---|---|---|
| 源代码 | 全部模块的源码（前端、后端、移动端、脚本）；能对上交付的版本；不带依赖包、编译产物、真实口令 | 和线上或演示的版本对得上；能从源码构建出来 |
| 需求或设计文档 | 功能清单、业务规则；大项目要有架构、数据库设计 | 和代码对：文档写了的功能代码里有没有 |
| 用户使用手册 | 登录和账号；**每个功能模块**的操作步骤；角色和权限说明；截图；常见问题 | 对照菜单逐个看有没有写到；照手册操作几项看对不对 |
| 部署手册 | 环境要求（系统、软件和版本、配置）；**全部配置项**的说明；数据库初始化；构建和启动步骤；部署后怎么验证；升级和回滚；备份；常见问题和排错 | **照着手册在干净环境装一遍**，装不起来就是不全；配置项和代码读的对一遍（底稿「配置一致性」） |
| 接口文档 | 每个接口的地址、方法、参数、返回、错误码、鉴权方式 | 抽几个接口和代码对：参数名、必填、返回字段 |
| 数据库脚本 | 建表脚本；初始化数据（字典、管理员）；历次升级脚本 | 在空库执行一遍；和代码里的实体对字段 |
| 构建和启动脚本 | 打包命令；启动停止脚本或容器配置；依赖清单（带版本、带锁文件） | 照着跑一遍 |
| 配置样例 | 不带真实值的配置样例，每项有说明 | 和代码读的配置项对 |
| 自动化测试 | 测试代码；一条命令能跑 | 跑一遍，记通过和失败数 |
| 测试报告 | 测试范围、用例、结果、遗留问题 | 和实际跑出来的对 |
| 版本说明 | 本版本改了什么、已知问题、升级注意事项 | 和提交记录对 |
| README | 项目是什么、目录结构、怎么跑起来 | 照着跑 |
| 许可证和第三方声明 | 代码归属；用到的开源组件及其许可 | 和依赖清单对；查有没有 GPL / AGPL 类组件 |

按项目类型补充：
- **App / 小程序**：安装包、签名证书和密钥的交接方式、上架资料、隐私政策。
- **有对外接口或对接第三方的**：对接文档、测试账号、回调地址说明。
- **有运维要求的**：运维手册（监控、日志、备份恢复、应急处理）、服务器和账号交接清单（账号口令另行安全交接，不写进文档）。
- **验收类**：培训材料、验收报告模板、源码著作权说明。

判定口径：
- 「齐全」：内容要点都有，验过能用。
- 「不全」：有但缺要点、或照着做不下去。写清缺哪几项。
- 「缺失」：没有。
- 「不适用」：这个项目确实不需要（例如没有数据库就不要数据库脚本），写理由。
- 只有 README 写了几句部署命令，部署手册判「不全」或「缺失」，不能判齐全。
