# 飞书 markdown 加粗解析缺陷 —— 探针实验原始记录

> 定位时间：2026-10-30（第十六轮自动化任务期间）
> 方法：创建 8 个临时飞书文档，分别写入不同加粗模式，`docs +fetch --doc-format xml` 逐条读回，对比原始意图与实际渲染。
> 所有探针文档在实验结束后已用 `lark-cli drive +delete --file-token <id> --type docx --yes` 删除。

## 一、缺陷现象

用 `lark-cli docs +update --doc-format markdown --command append` 写入时，**同一段内多个 `**加粗**` 会被错误合并成一个大加粗块**。

- 文字**零丢失**，只是强调范围失真。
- 后果：原本「关键词加粗 + 其余正常」的排版，变成整段加粗。

## 二、探针矩阵与结果

### Z01 `**A**x，**B**` —— **触发合并**
本地写两个独立加粗段，实际渲染为 `**Ax，B**`。

### Z02 `**A**x；**B**` —— **触发合并**
分号与全角逗号行为一致。

### Z03 `**A**x。**B**` —— **触发合并**
句号同样触发。

### Z04 `**A**x， **B**` —— **不触发**
`B` 前有半角空格 → 保持两个独立加粗段。

### Z05 `**A** x，**B**` —— **不触发**
`A` 后有半角空格 → 保持独立。

### Z06 `**A**"x"，**B**` —— **不触发**
引号紧贴加粗段，不构成「CJK+全角标点」组合。

### Z07 `**A**x**B**` —— **不触发**
两段之间无标点分隔。

### Z08 `**A**，**B**` —— **不触发**
标点两侧相邻，整段本身只有加粗内容。

### X02 `**A**x，**B**x，**C**` —— **触发，且向后吞并**
三个加粗段**全部**合并成一个。说明缺陷不是「两两合并」，而是从第一个加粗段一路吞到最后。

### XML 探针 —— 10/10 保真
用 `--doc-format xml` + 显式 `<b>` 标签写入，加粗边界**全部正确**，包括含行内 `<code>` 的段落。

## 三、规律归纳

**触发条件**（近似充分必要）：
1. 同一段内出现 ≥2 个 `**加粗**`；
2. 相邻两个加粗段之间的分隔文本，同时含有 **CJK 字符** 与 **全角标点**（`，。；：、！？」`）；
3. 加粗段与分隔文本之间**没有半角空格**。

**规避手法（任选其一）**：
- 在第二个加粗段前加半角空格：`**A**x， **B**`
- 在第一个加粗段后加半角空格：`**A** x，**B**`
- 改用 XML `<b>` 显式标签（**最可靠**）

## 四、实战修复记录（2026-10-30 第十六轮）

### 影响面

| 版本 | 文件 | 漂移段落数 |
|---|---|---|
| V15 | `outputs/2026-10-29-程序化实现的用户痛点全景图.md` | 17 |
| V16 | `outputs/2026-10-30-程序化实现的用户痛点全景图.md` | 35 |

合计 34 段全部修复完毕，复验 **drift = 0**。

### 修复流程（34 段实测）

1. `docs +fetch --doc-format xml --detail with-ids` → 拿到全文块结构与 `block_id`
2. 用 `convert_md_line_to_xml.py` 把本地对应行转成 XML（code-aware）
3. 逐段 `docs +update --command block_replace --block-id <id> --doc-format xml --content @file`
4. 复验：重新 fetch，比对本地/远端每段加粗段数

### 踩坑（全部实踩）

| 现象 | 真因 | 处理 |
|---|---|---|
| 第一次 dry-run 显示 `&lt;b&gt;` | 转义顺序错：先转义了文本再插 `<b>` | 改为「抽 code 占位 → 拆 `**` → 最后转义文本」 |
| 某段 `ok=False`，重试返回 `degrade_code=1011` | 第一次后台批处理其实已成功，重试是 no-op | 不要重试，重新 fetch 复验 |
| 两段含行内 `<code>` 的漂移没被正则检出 | 反则被反引号打断 | 检测与转换都改成 code-aware |
| `drive +delete` 报 `confirmation_required` | high-risk-write 需显式确认 | 加 `--yes` |
| `--scope section --start-block-id <h1_id>` 拿不全内容 | scope 语义限制 | 改用 `--scope keyword --keyword "<标题>"` 逐段取 |

### 最终状态

- 飞书文档 revision 最终到 **69**
- V15 段落 drift = 0，V16 段落 drift = 0
- 8 个探针文档已全部删除

## 五、下次写入的规矩

1. **写入端改用 XML + 显式 `<b>`**；如果坚持 markdown，源码层在相邻加粗段间插半角空格。
2. 写完**必做全量比对**（本地每段 `**` 计数 vs 远端每段加粗段数），不能只看标题层级。
3. 不要用 `--scope outline` 当作「写成功了」的证据 —— 它只给标题，正文里的加粗漂移它查不出来。
