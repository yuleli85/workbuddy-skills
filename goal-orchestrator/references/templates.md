# 模板库

## §1 作战计划（第 1 步产出，展示给用户后立即开工）

```markdown
## 作战计划 · <目标短名>

**目标**：<一句话复述>
**判定**：组队执行 / 直接执行（原因）
**关键假设**（信息不足处的显式假设，用户可随时纠正）：
1. <假设> → 影响 <范围>

**任务分解**：

| # | 任务 | 员工 | 依赖 | 验收标准 |
|---|---|---|---|---|
| T1 | <祈使句任务> | <代号> | — | <可观察的验证方式> |
| T2 | … | … | T1 | … |

**产物目录**：`<workspace>/output/task-list/<目标短名>/`
**质量门**：qa 验收，最多 2 轮打回
**预计交付**：<产物形态概览>

<含 🔴 不可逆操作时：列出待确认项，先等用户>
```

## §2 员工 spawn prompt 骨架

```markdown
你是 <角色名>（<代号>），数字员工团队的一员。只做本任务边界内的事。

## 背景与目标
<目标一句话 + 与本任务相关的上下文。子代理看不到会话历史，全部背景写在这里。>

## 你的任务
<祈使句描述 + 边界：明确"不做"什么，防止越界改坏别人的产物。>

## 验收标准（逐条自检并在汇报中给出证据）
1. <可观察标准，如：pytest 全绿 / 页面能打开并截图 / 文档包含 X 章节>
2. …

## 项目硬规则（必须遵守）
<从项目 AGENTS.md / 规范提炼的红线，3~8 条。无则写"无特殊约束"。>

## 产物落点
全部写到 `<产物目录>/`：<具体文件名约定>。
不修改本路径之外的任何文件；不改其他员工的产物。

## 汇报格式（完成后按此回报）
1. 做了什么；2. 产物路径清单；3. 自检结果（跑了什么、输出是什么）；
4. 遗留问题 / 需要主编排者裁决的事项。
```

打回重做时附加：

```markdown
## 打回单（第 N 轮）
未通过验收标准 #<k>：「<标准原文>」
现象：<实际> 期望：<应然>
证据：<命令输出/文件行号/截图>
请只修复该缺陷，不要扩大改动范围。
```

## §3 交付报告（第 6 步，写 `<产物目录>/交付报告.md`）

```markdown
# 交付报告 · <目标短名>

## L0 结论
<一句话：目标是否达成 + 完成度。有未通过项就直说，不粉饰。>

## L1 任务完成表
| # | 任务 | 员工 | 验收 | 质量门轮次 | 产物 |
|---|---|---|---|---|---|
| T1 | … | fe-dev | ✅ | 1 轮通过 | <路径> |

## L2 文件清单与使用方式
| 文件 | 是什么 | 怎么用（命令/打开方式） |

## L3 已知风险与遗留
<质量门 2 轮后仍未通过的项如实列出：缺陷、影响、建议处置。没有则写"无"。>
```

## §4 下一步清单（交付回复的固定结尾）

```markdown
## 下一步需要你做什么

🔴 必须决策（不决定无法继续）：
1. <事项> → 选项 A <…> / 选项 B <…>，我的建议：<…+理由>

🟡 建议验收（5 分钟内可完成的复核动作）：
1. <看哪个文件/跑哪条命令/点哪个页面，预期看到什么>

⚪ 可选优化（下期再说）：
1. <改进项>
```

三档全空时只保留 🟡 一条最简验收动作，不输出空标题。

## §5 员工日报（项目有 `数字员工/<角色>/` 约定时留档）

```markdown
# <角色名> · <YYYY-MM-DD>

> 目标：<目标短名>｜编排：主编排者｜纪律：<只读/改动范围声明>

## 一、任务来源与取舍
## 二、完成内容（对照验收标准逐条）
## 三、实际执行输出（命令 + 关键输出，不贴大段日志）
## 四、文件清单（文件/动作）
## 五、遗留问题 / 需要用户确认
```

与项目既有 `数字员工/` 目录的历史日报格式保持一致；无此约定的项目跳过本模板。
