# 仓库源码全维度体检

**目标**：一次调用产出「可复现、有证据、分级、零误报」的问题清单 —— 不是泛泛的「代码风格建议」。

## 核心原则

1. **只诊断，不修改**（用户说「扫描」「列出来给我看」= 只读）。修改是下一个任务。
2. **每条结论必须有可复现证据**：`文件:行` + 复现命令。没有证据的不写。
3. **误报要主动澄清**：宁可少报，不可假报。假报会让用户去修不存在的问题。
4. **优先级排序**：安全 > 编译/契约 > 卫生 > 质量。P0 必须带具体处置命令。

## 执行步骤

### 1. 先用现成脚本起飞（若仓库里已有）
本工作区已有：`tools/source_scan.py`（维度 `secrets|gitignore|frontend|java|python|drift|todos|size`，支持 `--only`）。
```bash
python3 tools/source_scan.py              # 全量
python3 tools/source_scan.py --only secrets
```
若目标仓库没有该脚本，按 §维度清单 手工跑（用 `Grep` 工具，**不要用 shell `grep` 做否定判断**）。

### 2. 按维度扫描（每维都要跑，别跳）
| 维度 | 判据 | 为什么重要 |
|---|---|---|
| 凭据入版本库 | `git ls-files` 里的 `.env*`、`git grep -lF '<key字面量>'`、源码里 `key= '长字符串'` | 唯一「泄漏即不可逆」的一类 |
| `.gitignore` 失效 | 逐条规则对 `git ls-files` 求交集 | **gitignore 对已跟踪文件完全无效** —— 规则在但文件照样被提交，是最隐蔽的一类 |
| 前端契约 | `url:` 前缀、硬编码服务地址、模板上屏的 `Number()` | 违反 C-03 / 直接上屏 `NaN` |
| Java 配置 | `*.yml`/`*.properties` 的口令字面量（排除 jasypt/占位） | 与「Spring 配置外置」基线相关 |
| Python | `compileall` + 仓库自己的导入门禁脚本 | 编译过 ≠ 启动得过 |
| 漂移 / 超长 | 同名文件跨端 md5 比对；`>800` 行文件 | 单端漂移是高频根因；超长文件是回归面 |
| 待办标记 | **注释形态**的 TODO/FIXME（见下方陷阱）| 找出「仍在用 mock 的伪功能」——比代码风格值钱得多 |

### 3. 交叉核验（**禁止跳过**）
每条 P0/P1 结论，在写进报告前必须做一次「反向验证」：
- 命中的字符串是**代码**还是**文案/注释/枚举值**？
- 文件是**被跟踪**的还是本地未跟踪的？（`git ls-files --error-unmatch <f>`）
- 值是真凭据还是占位符（`<...>` / `${VAR}` / `your_` / `xxx`）？

### 4. 产出
- 报告写成 `.md` 落到仓库（用 gitignored 的 `output/` 更安全：`output/audit-source-YYYY-MM-DD.md`）
- 结构：总览表 → P0（含处置命令，标注「未执行」）→ P1 → P2 → **已达标清单** → **误报澄清** → 复现命令
- **「已达标清单」不可省**：用户需要知道哪些维度是干净的，否则会重复焦虑。
- 用 `present_files` 把报告推给用户。

## 🔴 本类任务的头号陷阱：`grep` 假报 0

实测（2026-10-04）用 `grep -rnE '(TODO|FIXME)\b'` 得到「**0 处**」，改用 Python `re` 重扫是 **46 处**。
原因是主机上的 `grep` 是 brokered shim，**不支持 `\b` / `\|` / `\s`**，**静默 0 匹配** —— 不是报错，是安静地撒谎。

**规则**：
- 否定性结论（「没有 X」）**绝不能用 shell grep 得出** ⇒ 用 `Grep` 工具（ripgrep）或 Python `re`。
- 非用不可时：把 `\b` 写成显式边界、`\s` 写成 `[[:space:]]`、`\|` 写成 `grep -E 'a|b'`。
- 报告里凡是「0 命中」，都要写清是**哪个工具**得出的。

## 🔴 三类高频假阳性（写报告前必须过滤）

| 假阳性 | 实例 | 过滤方式 |
|---|---|---|
| **文案 / placeholder** | `placeholder="…例如：http://192.168.110.172/v1/workflows/run"` 被判为「前端直连」 | 跳过含 `placeholder` 或行首是注释的行 |
| **枚举值 / 业务数据** | `pig-ops` 的 `DwEtlMapper.java` 里 `WHEN 'wait' THEN 'TODO'` —— `TODO` 是禅道状态枚举，不是待办 | 只认 `// TODO` `/* TODO` `# TODO` 这类**注释形态** |
| **上游模板 / 第三方样例** | `dify-docker/**/*.env.example`、`node_modules/**` 里成百条 `PASSWORD=difyai123456` | 先判「这是不是我们自己的代码」；上游模板单独说明、不计入缺陷 |

## 🔴 误报四分类（2026-10-04 实战补录，**必读**）

「凭据扫描」是误报重灾区。实测一轮 26 条 P0 里，**只有 6 类是真凭据**，其余全是下面四类。
结论：**扫描器必须把这四类判掉**，否则用户会去修不存在的问题（和「假报 0」一样有害）。

| 类 | 典型样本 | 判定规则 |
|---|---|---|
| **① 占位符** | `DIFY_APP_KEYS={}`、`DIFY_DB_DSN=postgresql://u:<password>@h/db`、`xxx`/`your_`/`change-me`/`set-me` | 值里出现 `${VAR}`、`<...>`、`{}`、`[xXyY0]{5,}` 或行首关键词 ⇒ 放行。**注意占位符可能在值中间**，必须 `search` 不能 `match` |
| **② 已知共享约定值** | `SECURITY_ENCODEKEY`=`VITE_PWD_ENC_KEY`（被烘焙进前端产物 ⇒ 设计上公开）；PIG 上游同类 `mzlc:mzlc`/`app:app`/`social:social`；文档化默认 `admin/123456` | 维护白名单**并打印一行「已知开发约定值」**（不要静默吞掉），注明「生产必须覆盖」 |
| **③ 上游模板** | `dify-docker/**`、`deploy/dify/**` 里 Dify 官方发布的 `difyai123456` / `WVF5YTha…` | 按目录前缀排除，单列一条「上游模板，故意保留」，**不要改上游文件**（制造维护漂移） |
| **④ 测试夹具 / 头名 / 业务字段** | `ApiKeyTokenTests` 的 `sk-…-XyZ`；`INTERNAL_TOKEN_HEADER = "X-Internal-Token"`；`metric_key` / `output_key` / `cursor_key`；i18n 的 `url: 'URL格式有误'` | 路径含 `/test/`、值为 `X-*` 头名、变量名以 `_key` 结尾但不是 `api_key/access_key/private_key` ⇒ 放行 |

**反过来的坑（正向误报）**：把「上游源文件」当唯一依据会漏掉**我们自己在 `.env.example` 里抄了真值**
——所以「文件是否被跟踪」+「值是否占位」两个判断要同时做。

## 🔴 两个必查的「假达标」

1. **`grep` shim 假报 0**：本机 PATH 的 `grep` 是 brokered shim，**不支持 `\b` / `\s` / `\|`**，
   会**静默 0 匹配**（不报错）。凡是「扫到 0 处」的**否定性结论**，必须用 Grep 工具或 Python `re` 复核。
   实战案例：`grep -rnE '(TODO|FIXME)\b'` 得 0 处 → Python `re` 重扫是 **46 处**。
2. **`.gitignore` 冲突项要单独成条**：「声明忽略但实际被跟踪」= `.gitignore` 对已跟踪文件无效。
   这条比「env 文件里有值」更能反映真实卫生度，**必须单独检查、单独计数**（期望值 0）。

## 报告口径要求

- 修复前后数字必须可比 ⇒ **修脚本与改代码不要混在同一次报告里**，或者明确写出「本次同时升级了扫描器口径」。
- 每条 P0 都要给：`文件:行` + 复现命令 + **具体处置命令**（不是「建议检查」）。
- 明确区分「已修」与「需你决定」：密钥轮换、历史清洗、功能开发（mock→真接口）**永远属于后者**。

## 🔴 改文件的工程纪律（扫描后动手时）

- **改 GBK 编码文件（Windows `.bat`）必须「先 `encode()` 校验、再 `write_bytes`」**：
  `Path.write_text(encoding='gbk')` 是**先截断、后编码**，编码失败会把文件变成 **0 字节**。
  正确姿势：`blob = text.encode('gbk'); path.write_bytes(blob)`。且**不要在 .bat 里加 emoji**。
- **不要在一条消息里对同一文件并发多个 Edit**（实测会静默丢改动）⇒ 逐个改、改完回读。
- 批量替换用 Python 脚本 + `assert t.count(old) == 1`，替换完 `grep -c` 复验。
