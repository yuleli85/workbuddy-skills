# 一次性定时任务（once-task-scheduler）

把「**某个时间点 + 干一件事 + 只干一次 + 必须干完**」变成一个真的会在那时候跑完的自动化。

## 为什么这件事不能只靠"叮嘱"

WorkBuddy 的一次性自动化到点会**新起一个会话**执行那段 Prompt。那个会话：

- 没有当前对话的任何上下文；
- 不知道自己是不是已经跑过；
- **信息缺一点时，模型的默认行为是停下来问用户**。

而一旦它问出"需要我确认一下吗"，这个回合就结束了 —— 没有第二次机会，任务永久挂在那里，而界面上看起来一切正常。这就是"一次性任务"最常见的死法，不是失败，是**静默悬停**。

所以本技能的关键不是提醒模型"要一次做完"，而是：

> **把 Prompt 写成无法反问、无法半途收尾的形状，并在注册前用脚本机械校验。**

## 5 条硬约束

| 编号 | 约束 | 不满足时会发生什么 |
|---|---|---|
| **C1** | 自包含：绝对路径 + 完整命令 + 产物位置 | 到点的会话找不到"那个文件"，然后问你 |
| **C2** | 禁反问：写死"绝不提问"，并给出缺失信息的兜底决策表 | 一句"要不要我…？" ⇒ 回合结束 ⇒ 任务永久悬停 |
| **C3** | 终止判据机器可判：`test -s` / 退出码 / 条数 == N | 模型"总结"一下就收尾，实际什么都没落地 |
| **C4** | 单回合预算：全部步骤能在一个回合内跑完 | 中途被截断，没有接力机制，等于白跑 |
| **C5** | 成败都留痕：run 记录 | 事后分不清"没做"和"做了但没说话" |

C1/C2 是**硬门槛**（preflight 里 FAIL）；C3/C4/C5 是警告（WARN），建议逐条消化。

## 工作流

### Step 0 · 先判断"这件事能不能一次跑完"

这是整条流程里**唯一应该向用户开口的时刻**（注册前，不是执行时）。

| 情形 | 处置 |
|---|---|
| 预计 < 5 分钟、无人审批、无外部回执 | ✅ 直接做成一次性任务 |
| 要等外部事件（等 CI、等对方回消息、等构建） | ❌ 不能做成"到点跑完"。改成**轮询 N 次后放弃**的写法，或拆成两个任务 |
| 需要用户拍板（选方案、确认付款、确认收件人） | ❌ 拆成"到点生成选项 + 按默认项执行"，**默认项必须写进 Prompt** |
| 预计远超一个回合（如全量重构、批量转码几小时） | ❌ 拆成多个小任务，每个都在一次内可完成 |

一句话判据：**如果这件事的结果依赖"另一个人/另一个系统之后再回话"，它就不是一次性任务的料。**

### Step 1 · 改写成自包含 Prompt

用 `references/prompt-template.md` 的 6 段骨架。核心动作是**把"我"替换成"路径"**：

- ❌ `把刚才那个报告发给张总`
- ✅ `把 /Users/shan/WorkBuddy/日常工作/report-20261024.md 用 lark-cli 发到 open_id=ou_xxx`

**禁用词表**（出现即必须改）：

| 别写 | 因为 | 改写 |
|---|---|---|
| 刚才 / 之前 / 上面提到的 | 跨会话没有"刚才" | 绝对路径 |
| 当前目录 / 这个项目里 | 到点 cwd 不一定对 | 绝对路径 + 在 Prompt 里写死 |
| 是否需要 / 要不要我 / 可以吗 | 直接导致悬停 | 「按默认值执行并记录」 |
| 你确认一下 / 告诉我 | 同上 | 删掉，改成默认分支 |

### Step 2 · 跑 preflight（不通过不许注册）

```bash
python3 ~/.workbuddy/skills/once-task-scheduler/scripts/preflight.py \
   --at "2026-10-25T09:00" --file /tmp/once-prompt.md
```

脚本只用 Python 标准库（3.8+ 即可），不需要装任何依赖。

输出 `[PASS] / [WARN] / [FAIL]` + 每条的具体修法。**退出码 1 表示有 FAIL，禁止注册。**

脚本检查 7 项：跨会话指代、绝对路径、反问语、兜底决策、终止判据、单回合预算、时间是否在未来。其中「时间在未来」也在校验范围内 —— 一次性任务设在过去不会补跑。

### Step 3 · 注册

```python
automation_update(
    mode="create",
    name="[一次性 10-25 09:00] 导出上周订单对账",   # 名字带时间，便于台账识别
    scheduleType="once",
    scheduledAt="2026-10-25T09:00",          # 本地时间，无时区
    status="ACTIVE",
    cwds="/Users/shan/WorkBuddy/日常工作",     # 必须绝对路径，否则 cwd 是默认目录
    prompt=<Step 1 的产物>,
)
```

- `scheduledAt` 传本地时间即可，工具内部转 UTC；返回里看到 `nextRunAt` 是毫秒时间戳，`...Z` 结尾是正常回显。
- `cwds` 不填，到点时的 `cwd` 是默认工作目录，相对路径全废 —— 这是在 C1 之外单独要防的一层。
- `name` 建议固定格式 `[一次性 MM-DD HH:MM] <任务名>`，`scheduler-board` 看板里一眼能认出。

### Step 4 · 交付话术（别只说"已创建"）

回给用户必须含三项：**几点触发 / 具体做什么 / 结果在哪看**。例如：

> 已排：10-25 09:00 执行，把 `orders.csv` 里 T-1 订单导出为 `reports/20261024.xlsx`。
> 判据是文件存在且行数 > 0。结果会写到 `.../once-runs/20261025-0900/`，结束后我会回一行摘要。

### Step 5 · 执行完要清台账（真实踩过的坑）

**一次性任务跑完不会自动下线。** 本机 `automation_update(list)` 里就挂着一个 2026-10-11 的一次性任务，至今状态仍是 `ACTIVE`。不管它会越积越多，且下次看到时无法判断"到底跑没跑"。

两种处置，任选其一：

**A. 让任务自己下线（推荐，闭环）**
注册拿到 `id` 之后，再 `update` 一次，把 id 写进 Prompt 末尾，让执行会话在收尾时自我暂停：

```
# 自我清理
本自动化的 id 是 <automation_id>。
全部步骤完成后，调用 automation_update(mode="update", id="<automation_id>", status="PAUSED") 把自己停掉。
```

注意：`status="PAUSED"` 是停用，不是删除；保留记录便于审计。要彻底清掉用 `mode="delete"`。

**B. 交付时明确告诉用户"跑完记得删"**，并给出可复制的清理动作。省事但依赖人不忘记。

## 状态落盘（可选，但强烈建议）

C5 不是硬门槛，但只要这件事有副作用（发消息、写数据库、调用外部 API），就值得加一个 5 行的 run 记录：

```
RUN_DIR=/Users/shan/WorkBuddy/日常工作/once-runs/20261025-0900
mkdir -p "$RUN_DIR"
echo "START $(date -Iseconds)" >> "$RUN_DIR/run.log"
# ... 干活 ...
echo "DONE $(date -Iseconds)" >> "$RUN_DIR/run.log"
```

同时在 Prompt 开头加一句**幂等保护**：

```
# 第 0 步
若 /Users/.../once-runs/20261025-0900/run.log 中已含 "DONE"，说明本任务已完成，
立即输出 ALREADY_DONE 并结束，不要重复执行任何有副作用的步骤。
```

这一句挡住的是：用户手动重跑、多会话并发、以及"看到没动静又点了一次"这三类重复执行。

## 检查清单（注册前逐条打勾）

- [ ] 这件事**不依赖外部回话**，一个回合能跑完
- [ ] Prompt 里没有一个"刚才/之前/当前目录"
- [ ] 没有一个"要不要/是否/确认一下"
- [ ] 至少一条绝对路径（输入 + 输出）
- [ ] 有兜底表：X 不存在时用默认 Y；Y 也没有就跳过并记录
- [ ] 终止判据是机器判的（`test -s` / 退出码 / 条数）
- [ ] `cwds` 是绝对路径
- [ ] preflight 退出码为 0
- [ ] 有副作用的，加了 run 记录 + ALREADY_DONE 幂等保护
- [ ] 已经想好：跑完之后谁来把这条自动化停掉

## 与其它技能的边界

- 只要**定期重复**（每天/每周）→ 不走本技能，直接建 `recurring` 自动化；若要看板上已有的任务用 `scheduler-board`。
- 要**在服务器上**按 cron 跑、跟 WorkBuddy 无关 → 本技能不适用（本机也无法从会话内注册系统级 launchd/cron）。
- 本技能负责的是「**一次性的、到点必须自己跑完的、WorkBuddy 内的一次性自动化**」。
