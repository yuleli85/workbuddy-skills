# 一次性任务的 7 种真实死法

按「有多难发现」排序 —— 越靠前越隐蔽。前 3 种在界面上看起来都像"正常完成"。

---

## 1. 静默悬停（最致命）

**症状**：到了时间，一切正常，没有报错。但什么都没发生。翻会话记录才看到最后一句是「请问是要发送到 A 群还是 B 群？」

**根因**：到点触发的是**一次性回合**。模型遇到歧义时，礼貌地征询确认 —— 而这一问之后没有任何机制会再唤醒它。任务不是失败，是**永久暂停且无人知晓**。

**修法**：
- Prompt 写死「绝不提问，绝不请求确认」；
- 给出缺失信息的兜底决策表（缺什么 → 用哪个默认值 → 都拿不到就跳过并标注）；
- 有副作用且涉及"发给谁/给谁看"的，明确写死目标 id，并加「不得猜测收件人，失败即 FAIL」。

**preflight**：`C2 禁反问`（FAIL）、`C2 缺失信息兜底`（WARN）

---

## 2. 提前收尾

**症状**：会话里模型说「已完成，报告已生成」，但去目录里找不到文件；或者文件是 0 字节。

**根因**：没有机器可判的完成条件，模型以"我已经解释清楚了"作为完成标志。它总结的是**意图**，不是**结果**。

**修法**：终止判据必须是命令级的客观事实 —— `test -s <file>` 退出码 0、`wc -l` 等值、`curl` 返回 200、数据库 `count(*) == N`。并在步骤末尾真的跑一次这个校验。

**preflight**：`C3 终止判据机器可判`（WARN）

---

## 3. 上下文失忆

**症状**：报错「文件不存在」「目录不存在」，而那个文件明明在。

**根因**：Prompt 里写了「刚才那个报告」「当前项目」。到点的会话在一个全新的环境里，"刚才"指向不存在的过去，"当前目录"是默认工作目录而不是你注册时的 cwd。

**修法**：
- 所有输入/输出写**绝对路径**；
- `automation_update` 的 `cwds` 必须填绝对路径；
- 需要环境变量、venv、特定 CLI 的，把完整调用路径写进 Prompt（例如直接写 `/Users/shan/.workbuddy/binaries/python/envs/default/bin/python`，而不是 `python3`）。

**preflight**：`C1 自包含`（指代词 FAIL、绝对路径 WARN）

---

## 4. 中途截断

**症状**：任务跑到一半没了；或前 60% 的产物存在，后 40% 缺失。

**根因**：任务本身超出单个回合的承受范围。一次性任务**没有接力机制** —— 回合结束即终结，不存在"下次继续"。

**修法**：在注册前就把任务拆到"一个回合能做完"的粒度。如果实在要跑长任务，把长任务写成**一个幂等的可重入脚本**（脚本自己带断点续跑），Prompt 只负责启动它并等待退出码。

> 判据：需要等外部事件（CI、对方回信）或预计远超 5 分钟的，都不该做成一次性任务。

**preflight**：`C4 单回合预算声明`（WARN）

---

## 5. 重复执行

**症状**：同一条消息发了两遍；同一个文件被追加了两次；数据库多了一批重复行。

**根因**：三种来源都会触发 —— ① 看到没动静，手动点了一次；② 两个会话并发；③ 重试逻辑没做幂等。

**修法**：
- 第 0 步做幂等检查：`run.log` 里已有 `DONE` 就直接结束；
- 副作用动作前先查"是否已存在"（消息用 message_id、文件用标记文件、数据库用唯一键）；
- 交付输出 `ALREADY_DONE` 而不是报错。

**preflight**：`C5 成败留痕`（WARN）

---

## 6. 环境漂移

**症状**：同一段命令，你手动跑得好好的，到点跑就报 `command not found` 或连不上服务。

**根因**：到点执行时的环境与注册时不同 —— PATH 里没有自定义 CLI、venv 未激活、需要的本地服务已经停了、代理环境变量仍在。

**修法**：
- 所有二进制写绝对路径；
- 对依赖本地服务的任务，第 1 步先探活（`lsof -nP -iTCP:<port> -sTCP:LISTEN`），不通就按兜底表处理，别直接干；
- 本机 curl 探测回环会走系统代理，判断服务是否真活着要加 `--noproxy '*'`。

**preflight**：不覆盖（属于内容质量，需人工检查清单把关）

---

## 7. 台账残留

**症状**：几个月后打开自动化列表，一堆早该消失的一次性任务还挂着 `ACTIVE`，无法判断到底跑没跑。

**根因**：**一次性任务执行完不会自动下线**。本机就存在一个 2026-10-11 的一次性任务，到 10-24 仍是 `ACTIVE`。

**修法**（见 SKILL.md Step 5）：
- 注册拿到 `id` 后，把 id 回填进 Prompt 末尾，让任务自己在收尾时 `status="PAUSED"`；
- 或交付时明确提示用户"跑完删掉"，并给可复制的动作；
- 定期用 `scheduler-board` 查看板里的 `once` 残留。
